先分清：两种常见做法

CONCEPT A VS B

这一段是正文演示，用来展示行内标记。常见的误区是边出边改：先蹦出一串结果，后面又把自己推翻，下游很容易出错。

我们要强调的是append-only这类关键术语：只追加、不回改。稳定结果一旦提交，后面再来数据也不会推翻前面的结论，用一句话概括就是落子无悔。

一张表看懂差异

维度做法 A（可回改）做法 B（只追加）
已出结果可能被改写永久提交
观感容易闪烁更稳定
下游消费动作可能被推翻可立刻使用
接入成本需额外处理链路更简单

读表注意

带 ※ 的项目只是演示数据，不代表真实结论；正式对比请以你自己的实测为准，这里仅展示表格与警示框的写法。

怎么快速判断

盯结果 10 秒：如果已经出现的内容又被「回头改掉」，就是会回改的做法；只追加、不回改的才是稳定做法。

本地三步跑通

QUICK START

演示环境建议用隔离的虚拟环境，Python 版本以3.12为例（3.10+ 一般也可用）。想少踩依赖兼容坑，直接用 Docker 更省事，镜像名可写成 your-name/demo:latest 这样的占位。

STEP 01

拉代码、建环境

先克隆示例仓库，再建一个干净的虚拟环境，避免污染本机依赖。

bash

git clone https://example.com/your-name/demo-project.git

cd demo-project

conda create -n demo python=3.12 -y

conda activate demo

pip install -e .

STEP 02

准备输入，跑通一次

准备一个示例输入文件，程序内部会自动做格式校验；下面的路径都换成你自己的。

bash

./run_example.sh /path/to/input.wav \

--model_path /path/to/demo-model \

--mode stream \

--language Chinese

STEP 03

监听输出，确认稳定

监听流式输出，确认已提交的结果不再回改，再接你自己的业务逻辑。
