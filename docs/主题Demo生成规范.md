# 主题示例 Demo 生成规范

> 适用：公众号排版工坊（wx-layout）。**每提取 / 复刻出一套新主题，都必须在同一流程里
> 自动产出一份“覆盖该主题全部样式”的示例 demo，并渲染出示例文件。**
> 目的：提取完即可见效果；用户在可视化工作台里能对照每一种格式的写法、自行替换内容。

---

## 1. 触发时机

主题提取是「确定性脚本 + 大模型归纳」协作完成的（见 `tools\extract_dom.py` 与提取 skill）。
生成 demo 是提取流程的**固定收尾步骤**，与主题文件一起交付，不可省略：

```
extract_dom 抽取 DOM/样式
  → 大模型语义归纳、生成 themes\<主题>.py
  → 【本规范】scaffold_demo 生成覆盖全部样式的 demo 源稿
  → 大模型按本规范润色 demo 文案
  → render.py 渲染出示例 HTML
  → 主题 + demo 一并入库
```

---

## 2. 产物与命名约定

每个主题对应两个文件，统一放在 `examples\`：

| 产物 | 路径 | 说明 |
|---|---|---|
| demo 源稿 | `examples\demo-<主题文件名>.md` | 含全部模块与写法注释，可编辑 |
| 渲染示例 | `examples\demo-<主题文件名>.html` | 该主题渲染结果，随仓库提交 |

例：主题 `themes\暖棕手记.py` → `examples\demo-暖棕手记.md` / `.html`。

> 注意与另一类文件区分：`examples\demo.md` 是**跨主题共享源稿**（在浏览器里按所选主题渲染，
> 用于跨主题 / fallback 测试），它在纯网页里由 `samples.js` 内联；本规范的 `demo-<主题>.md`
> 是**该主题专属、穷尽自身特有写法**的示例，两者不冲突。

---

## 3. 覆盖率要求（最重要）

demo 必须让该主题**每一种可见样式至少出现一次**，由确定性脚本保证不遗漏：

1. **每一个自有 role**：`themes\<主题>.py` 的 `ROLES` 中每个 role 各一个示例。
2. **每一个位置槽**：role 函数里 `b.get(N)` 取到的每个槽位都要给值（用占位文字）。
3. **每一个 kw 开关 / 变体**：`b.kw.get("x")` 控制的变体要额外给一个“开关打开”的示例
   （如 `shot` 的默认直角图与 `round=1` 圆角图各一张）。
4. **行内格式**：正文段落里演示内核行内 `**加粗**`、`[文字](https链接)`；
   以及**主题本地行内标记**（如暖棕手记的 `==高亮==`），每种标记都要出现。
5. **列表**：给出 `- ` 列表示例（`•` 由内核自动处理）。
6. **容器 body 的元素类型**：容器 role 若读取图 / 标题 / 列表 / 链接，则 body 里相应各放一个；
   主题不消费 body 的容器（如暖棕 issue 只用位置槽）则**不要**塞会被忽略的 body。
7. **未实现 role 的说明**：在文件顶部注释里列出该主题未实现、会走内核 fallback 的常用 role，
   并指向 `examples\demo.md` 看降级效果；**不要**把 fallback 模块混进主题专属 demo 渲染
   （避免成片灰色降级框干扰主题观感）。

---

## 4. 内容与占位规则

- 一律使用**占位符 / 中性演示文字**（如「文章标题占位」「这是正文演示段落，可替换成你的内容」），
  不写真实推广、不引用具体品牌或个人。
- **公众号/栏目名一律用醒目占位**：刊头里凡是账号名称的位置，写「【请改成你的公众号名称】」，
  日期写「【日期】」，**绝不替用户编造名称**；交付时提醒用户替换。
- 文案可简短，但每个模块要能一眼看出“这是什么、该填什么”。
- 单个文件、结构按真实文章顺序组织（刊头 → 章节 → 正文 / 截图 / 引用 / 视频 / 卡片 → 结尾 / 作者）。

## 5. 图片规则（遵守内核约束）

- 图片地址**必须是 `https://`**，禁止本地路径（内核不支持）。
- 脚手架默认用占位图 `https://placehold.co/600x400?text=Demo`（离线可能不显示，仅占位）。
- **大模型润色时**：优先从该主题提取产物 `tools\analysis\<文章>.dom.json` 里取该主题真实出现过的
  图片 URL 替换占位图，使示例尽量还原；取不到再保留占位图。

---

## 6. 写法自文档化

demo 同时是“写法说明书”：

- 每个模块**上方**用 HTML 注释写出该行的确切写法，例如：
  `<!-- 写法：:::part 编号|中文标题|英文标签（单行，无需闭合） -->`
- 容器注明“需另起一行 `:::` 闭合”，单行模块注明“无需闭合”；变体注明开关含义。
- 文件顶部用一段 HTML 注释说明：这是什么、怎么用、哪些 role 走 fallback。
- HTML 注释不会被渲染、也不会进入复制结果，不影响成品。

---

## 7. 生成与渲染命令

覆盖率由确定性脚本保证，文案由大模型润色（“代码执行、AI 看懂”）：

```powershell
# 1) 生成覆盖全部样式的 demo 骨架（并直接渲染）
python tools\scaffold_demo.py <主题文件名> --render

# 2) 大模型按本规范润色 examples\demo-<主题>.md（替换占位文案 / 换成真实图片）
# 3) 润色后重新渲染
python render.py examples\demo-<主题>.md --theme <主题文件名> -o examples\demo-<主题>.html
```

`scaffold_demo.py` 只读主题真实源码：枚举 `ROLES`、解析 `b.get` 槽位、`b.kw` 开关、
`b.fields` 读取项与 `re.compile` 定义的本地行内标记，自动产出带注释的 demo。

## 8. 验收清单

- [ ] `examples\demo-<主题>.md` 与 `.html` 均已生成。
- [ ] 该主题 `ROLES` 中每个 role、每个位置槽、每个 kw 变体都在 demo 中出现。
- [ ] `**`、链接、主题本地行内标记、列表均有示例。
- [ ] 刊头账号名/日期使用「【请改成你的公众号名称】」「【日期】」占位，未编造名称。
- [ ] 每段模块上方有写法注释；顶部注释列出了 fallback role。
- [ ] 图片均为 https；不消费 body 的容器没有多余 body。
- [ ] 渲染 HTML 能正常打开，无报错、无空白模块。
- [ ] 在工作台文件下拉中能打开该 demo 并正常渲染。
- [ ] **合并前过保真关**：`python tools\diff_style.py <原文> <完整复刻渲染.html>` 退出码 0
  （装饰条 / 边框 / 渐变 / 图片 / flex 一致；文字另由 `diff_render.py` 把关）。

---

## 9. 与可视化工作台的关系

工作台（`serve.py` / `工作台.bat`）在选中某主题后，可一键打开
`examples\demo-<当前主题>.md`：左侧看写法、右侧看效果，用户直接改内容、点「一键复制」即可。
新增主题只要按本规范产出同名 demo，工作台无需额外配置即可识别。
