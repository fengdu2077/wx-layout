# wx-layout · 排版器（只排版，不代写）

把用户**已写好的文章**排成可直接粘贴进公众号后台的成稿。
**AI 负责排版，程序负责精确渲染。**

## 职责边界（必须遵守）

- **只排版，不代写**：文章是用户写好的。**保留原文全部内容和顺序，不替用户写、不扩写、
  不缩写、不"润色"、不改写、不删句子、不加用户没说过的信息**。
- 只做这些事：按原意分段、加 `:::模块` 标记、把原文中本就是并列的内容整理成列表、
  给原文中本就是重点的句子加 `**加粗**`、保留原文已有的链接。
- 用户**没有成稿**（只有想法/素材/提纲）时：本 skill 不代写。让用户先把文章写完，
  或在普通对话中先完成起草、经用户确认后，再把**成稿**拿来走本流程。
- **不自己渲染、不手写最终 HTML、不臆造任何样式**；最终 HTML 只由 `render.py / wx_core` 生成。
- 不从已有公众号文章逆向主题（交给 `wx-theme-extractor`）；不自动登录后台、不群发
  （当前发布流程是手动复制粘贴）。

## 项目根与参数

- **项目根 `ROOT`**：本 skill 位于 `<ROOT>/skills/wx-layout/`，脚本会自动向上探测到
  含 `wx_core.py` 的项目根；也可用 `--root` 参数或 `WX_LAYOUT_ROOT` 环境变量指定。
- **主题 `THEME`**：默认 `蓝白杂志`。可用主题文件名 / label / 英文代号指定，
  不确定先 `--list-themes`。
- 主题的 role、字段、令牌一律以 `scripts/theme_contract.py` 的**实时输出**和主题源码为准；
  语义见 `references/模块速查.md` 与 `docs/AI排版手册.md`，禁止凭记忆臆造。

## 工作流

1. **确认输入**：拿到用户**已写好的文章全文（或 .md/.txt 文件路径）**与主题。信息不足时
   一次性问清：用哪个主题、截图/封面图地址、视频位置、需要的链接、栏目名与日期、作者信息。
   不要反复追问；用户没给的信息一律留占位，绝不编造。
2. **读取真实契约**（每次都做，不靠记忆）：
   ```bash
   # 在项目根 ROOT 下执行
   python render.py --list-themes
   python skills/wx-layout/scripts/theme_contract.py <THEME>
   # 也可显式指定项目根：python skills/wx-layout/scripts/theme_contract.py <THEME> --root <ROOT>
   ```
   并通读 `<ROOT>/docs/AI排版手册.md`；需要了解整套工具的机制背景时再看 `docs/项目架构蓝图.html`。
3. **组织结构**：按主题真正实现的 role，给原文安排刊头、章节（part/sub）、正文、截图、
   引用、卡片、视频位、结尾、作者名片。只使用该主题支持或可由内核 fallback 降级的 role。
4. **排版成 Markdown**：保存为 `<文章名>.md`（默认放在原文旁边，或用户指定位置）。
   **保留用户原文，只加 `:::模块` 标记与必要的列表/加粗/链接**，不改写内容；给全语义字段。
5. **渲染（走程序，不自行渲染）**：
   ```bash
   python render.py "<文章名>.md" --theme <THEME> --open
   ```
   生成 `<文章名>-wx.html` 并在浏览器打开；把输出路径告诉用户。
6. **引导复制粘贴**：提示用户在网页顶部点「**一键复制排版结果**」→ 公众号后台新建图文
   正文区 `Ctrl+V`；视频/小程序位置在后台手动插入真实内容；图片建议用后台
   `mmbiz.qpic.cn` 地址。
7. **改稿循环**：用户提出修改时，只改 `<文章名>.md`，然后重跑第 5 步重新渲染；
   **不要直接改生成的 HTML**。

## 排版铁律

- **保留用户原文**：不替写、扩写、缩写、改写或删句子；只加排版标记。
- 正文一段就是一段，**不**用全角空格或手敲空格凑缩进、不自己加空行凑版式。
- 图片必须是 `https://` 开头的网址，**不支持本地路径**；暂无图时写占位链接并在交付时
  明确告知用户后续替换。
- **公众号名称**：用户没给栏目/公众号名时，刊头一律写「【请改成你的公众号名称】」，
  日期写「【日期】」，绝不编造；交付时提醒用户替换。
- `issue`、`author`、`end` 每篇各一次；`part / sub / shot / quote / video / card` 可多次使用。
- 字段缺失时主题会自动 fallback 降级（不报错、不留白），无需硬凑；但应尽量写全语义字段，
  尤其 `:::card` 的 image/标题/摘要/链接。
- 主题可能有自己的扩展模块与行内标记（如翠绿科技的 `code/table/step/note` 与
  `==关键==` 等），**以该主题的 `examples/demo-<主题>.md` 与契约脚本输出为准**。
- 成稿 md 里不输出任何格式说明文字；需要用户手动替换的占位，在交付时口头列出。
